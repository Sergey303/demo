# Образец протокола проверки одной операции

Учебный образец формы результата первого оплачиваемого этапа.
Не отчёт о клиенте и не новый запуск тестов. Строки
с фактическим PASS ниже основаны на исторической проверке,
зафиксированной в README.md и tests/smoke.py.

## Объект проверки

Учебный приём текстовой операции /jobs. Ожидаемый эффект:
один идентификатор для одинакового ключа и payload, результат
в базе после завершения. Границы — локальный тестовый API
и PostgreSQL, внешний эффект отсутствует. В примере не проверяются
права, нагрузка, платежи и внешние системы.

## Матрица

| Проверка | Ожидание | Наблюдение и источник | Статус |
|---|---|---|---|
| 20 одинаковых запросов, один ключ | Один ID, ответы 200/202 | 05.11.2026 smoke.py: один ID, итоговые WordCount=3 и SHA-256 совпали | PASS (исторический) |
| Изменённое содержимое, прежний ключ | 409 | В том же smoke получен 409 | PASS (исторический) |
| Потеря ответа после commit | Повтор получает прежний ID | Не выполнен целевой тест с потерей ответа | NOT TESTED |
| Остановка worker между claim и commit | После восстановления один записанный результат | Проверка примитива SKIP LOCKED/rollback отдельно; процесс не прерывался | NOT TESTED |
| Исчерпание пяти ошибок обработчика | failed, нет дальнейшего автоматического исполнения | Реализация видна в коде; живой fault injection не проводился | NOT TESTED |

В расширенном техническом режиме использовать уровни свидетельств
из [TECHNICAL-JOURNEY.md](TECHNICAL-JOURNEY.md). Исторический smoke
не проверяет SQL counts и не доказывает 20 одновременных соединений.
Неизвестный исход commit отличается от подтверждённого rollback.

## Что получает заказчик

Для реального заказа вместо исторических примеров записать версию
проверенного кода, стенд, точные шаги, входные данные, ожидаемый
и фактический результат, доказательства (обезличенные журналы,
ID, строки БД или записи получателя), ограничения и рекомендацию.
Статусы PASS/FAIL/NOT TESTED не подменяются оценкой всей системы.
Если обнаружено нарушение, отдельно согласовать исправление и
регрессионную проверку. Если нарушение не воспроизведено,
протокол остаётся полезным результатом проверки, но не гарантией
отсутствия дефекта.
