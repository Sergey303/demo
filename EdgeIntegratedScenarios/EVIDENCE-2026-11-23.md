## Measured only inside the toy models

| Exercise | Observable behavior |
| --- | --- |
| BGP withdrawal | After announcements, chosen next hop: `edge-a → edge-a → edge-b → none → edge-c` |
| Anycast overload | Normal: `edge-a` 210 / capacity 150 requests/s, `edge-b` 50 / capacity 200 |
| Anycast failover | With `edge-a` down, `edge-b` handles 260 / capacity 200; two sessions are counted as interrupted |
| Heuristic on 12 **authored** examples | TP 3, TN 4, FP 2, FN 3; precision 0.60, recall 0.50, flagged false-positive rate 0.3333 |
| Rule-only on 12 **authored** examples | Flagged TP 1, TN 5, FP 2, FN 4; flagged recall 0.20 |
| Rule + anomaly advisory | Flagged TP 3, TN 4, FP 3, FN 2; flagged recall 0.60; **three extra observations**, two simulated model fallbacks, one benign case blocked **by the deterministic rule** |

In the combined scenario **flagged = observe OR block**; a higher flagged recall is **not** evidence of more attacks being blocked. AI advice changes only `allow` to `observe`, not to `block`.

## Limitations / unresolved claims

1. BGP and Anycast are simplified deterministic models, not measurements of ISP/Cloudflare/EdgeCenter/Yandex routing.
2. Synthetic scenario labels and the score are authored; the data are not independently sourced. No claim about real DDoS precision/recall is justified.
3. No HTTP 429 response, multi-instance rate limiter, L3/L4 filtering, WAF, or CDN configuration has been verified.
4. No ONNX or external inference runtime was run.
5. The Codex CLI implementation attempt encountered an execution-sandbox restriction; these files were implemented and checked directly in an isolated worktree. The `TASK.md` files remain the work queue.
6. GitHub Actions must be checked separately after the commit lands in `main`.
