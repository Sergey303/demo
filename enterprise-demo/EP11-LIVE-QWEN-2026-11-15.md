## Actual execution path

Two real headless Chromium sessions opened separate local Vite servers
(`127.0.0.1:4173` = Alice, `127.0.0.1:4174` = Bob).
Each Vite server supplied its own startup-fixed signed
`tenant=ep11-live-team`, `subject=alice|bob` bearer to the SAME
FastAPI process on `127.0.0.1:5088`.

Each browser submitted the actual task `When can customers request a refund?`
via `/enterprise-search/agent/run`. The real Qwen3:8b model selected the
`search_evidence` tool. The application used its official MCP client to
start the actual stdio MCP server, which queried a NEW disposable PostgreSQL
16 database with tenant-and-subject SQL grants. Retrieval used
`BAAI/bge-small-en-v1.5` through real FastEmbed/ONNX (384 dimensions).
The host validated the sources and model response and returned source-bound
citations. **No mock LLM, scripted tool call, mock browser HTTP or test encoder**
was used for this run.

Models: Ollama **0.40.15**, `qwen3:8b` manifest/model ID
`500a1f067a9f` (5.2 GB on disk, ~5.8 GB loaded CPU-only).
The two Qwen rounds per answer used the code's ordinary bounded adapter
(`think=false`, `num_ctx=3072`, `temperature=0`, up to 192 tokens per
round). A separate real warm-up completed in **17.66 s**.

### Revocation after inference

A trusted **offline administrator** revoked Alice's grant for her own
synthetic job. A subsequent signed HTTP search from Alice returned
`abstained=true, hits=[]`. A signed search from Bob still returned ONLY
Bob's original job. **PASS**. This validates a fresh read after revocation;
it does not assert that an already-rendered browser answer disappears
without a new request. Revoke-during-inference is separately covered by
the scripted-model, real-MCP/PostgreSQL regression suite.

## Environment, cleanup, and negative evidence

- This RDC uses separate filesystems: `/workspace` had about **7.5 GiB**
  free, but `/root` had over **860 GiB** free. Qwen3:8b was downloaded into
  the Ollama model directory under `/root`; the almost-full workspace disk
  was not used for model weights. BGE-small was cached on the root filesystem.
- Two preliminary infrastructure attempts were **not counted as model passes**:
  the first probed PostgreSQL before SQL initialization was complete;
  the second Docker default bridge could not be reached from RDC.
  The successful run waited for `SELECT 1` and used a new container attached
  only to the existing RDC Docker-control network (`172.29.*`), with random
  disposable DB credentials. No production/shared DB was opened.
- The successful run's temporary PostgreSQL container, FastAPI server,
  Vite servers, Chromium process and temporary frontend dependency link
  were terminated/removed after completion. The Ollama weights were retained
  for reuse; the runtime can be started separately on loopback.
- Synthetic records and random signing secrets were not persisted into Git.
  Run timings are two observations, **not** an SLA or performance benchmark.
  The test did **not** perform live human login, OIDC, full WAV transcription,
  automated note approval, blind semantic correctness evaluation or a
  revoke-during-Qwen race. Citations prove authorized provenance, not
  the truth of every generated statement.

**Engineering conclusion:** EP-11's two-profile browser-to-model-to-MCP-to-
live-SQL path and current-grant filtering are now independently exercised
with the real local Qwen3:8b and ONNX encoder. The model is still a bounded
assistant under trusted server-side principals, **not a production
multi-user authentication system**.
