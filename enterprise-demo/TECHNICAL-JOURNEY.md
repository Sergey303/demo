# Enterprise AI — технический маршрут для CTO и архитектора

27.11.2026. Спецификация P1, не новый запуск моделей.
Цель: показать, что именно контролируется, что измеряется отдельно,
и почему решение можно оценить на материалах заказчика.
Не расширять P1 до универсального агента или production IAM.

## 1. Пять независимых вопросов о доверии

| Вопрос | Проверка | Граница |
|---|---|---|
| Имеет ли сотрудник право читать источник? | Идентичность и актуальные grants до retrieval | Не production SSO; не защита ранее полученной копии |
| Найден ли нужный материал? | Recall по размеченным применимым фрагментам | Cosine не вероятность правильного ответа |
| Подлинна ли цитата? | Серверный источник, точный текст, диапазон, job ID | Правдивая цитата может быть нерелевантной |
| Следует ли вывод из материала? | Независимая оценка утверждений и их применимости | Валидный ID не доказывает entailment |
| Действует ли правило сейчас? | Версия, область применения, владелец, дата/приоритет | Автоматический контроль актуальности в live demo не доказан |

Первый экран технического режима: «Что подтверждено, а что нет».
Показать раскрываемую трассу, выбранный набор A/B/C, матрицу
доказательств и границы. Техническая панель не меняет бизнес-сценарий.

## 2. Два реально проверенных пути, не одна вымышленная архитектура

A (09.11): React/Vite localhost proxy → .NET API → PostgreSQL
jobs/outbox → Python worker → WAV Whisper tiny.en / Markdown
BGE-small EN ONNX → signed request /enterprise-search/answer →
SQL authorized retrieval → evidence_answer → optional guarded Qwen3:8b
→ JSON schema/citation IDs → повторная проверка ВСЕХ источников
переданных модели → response. Для evidence-only LLM не вызывается;
не приписывать этому режиму финальную проверку generated branch.

B (15.11): два независимых startup-fixed Vite principal →
FastAPI /enterprise-search/agent/run → Qwen tool selection →
официальный MCP stdio search_evidence → PG grants + ONNX →
server validation / recheck → Qwen final → recheck и проверка
токена → server-bound citations. Настоящий tool call, но не
неограниченный агент. Проверка B с двумя профилями не включает
реальную загрузку WAV или проверку approval note. Не показывать
в P1 запись в CRM, автоматические действия или подтверждение заметок.

Источники реализации: architecture/unified_search.py,
evidence_answer.py, guarded_generation.py, search_api.py,
mcp_agent_host.py, mcp_evidence_server.py. Публичный режим —
replay/учебная модель, не вызовы этих модулей.
Визуально помечать реальные компоненты как схему ранее
проверенного пути, а не текущий trace.

## 3. Что видит архитектор в технической панели

Развернуть «От вопроса до ответа»: вопрос, профиль учебный,
корпус, режим (replay / учебная выдержка / отказ / конфликт),
источник, диапазон, оригинал и перевод, вид доказательства.
Доступный источник можно открыть в пределах опубликованного
фрагмента, не выдавать ссылку на несуществующий полный файл.
Для B исходный ответ Qwen и название источника с UUID из протокола;
не синтезировать точный quote, если оригинал не предъявлен.
Не выставлять в браузере реальные токены, DSN, векторы, prompts,
фиктивные runtime trace и confidence. Не показывать закрытые
имена/метаданные как результат поиска; учебный перечень для
управления разрешениями отдельно маркирован как панель модели,
а не представление обычного сотрудника. Публичные fixtures
известны посетителю, их изоляция не security boundary.

### Точная сверка A

Фактический скриншот media/enterprise-generated-real.png:
- Ответ Qwen: “Customers can request a refund within 30 days.”
- refund-audio.wav, 0.00–3.00 с: “Customers can request a refund within 30 days.”
- refund-policy.md, символы 26–72: “Customers may request a refund within 30 days.”
Последнее также подтверждено fixture в bootstrap5/tests/enterprise-search-live.spec.ts.
Именно эти цитаты использовать в P1 replay, а не прежние упрощённые
строки public-demos/model.mjs. Не смешивать «can» и «may» и не
выдавать русский перевод за дословный оригинал. Протокол Qwen
и скриншот подтверждают этот конкретный ответ, не независимую оценку.

## 4. Архитектурные границы и выбор для клиента

| Слой | Текущий код | Вопрос перед внедрением |
|---|---|---|
| Источники | UTF-8 txt/md до 24 KiB, WAV до 256 KiB, синтетика | PDF/OCR, офисные форматы, языки, объём и обновления |
| Identity | server-side signed tenant/subject, фиксированные localhost proxy profiles | SSO/OIDC, жизненный цикл сессии, provisioning, tenant isolation |
| Retrieval | SQL grants до чтения сегментов; 100 последних jobs и 500 segments; точный cosine в Python, top_k 1–5 | Полнота поиска, масштаб, index/update ACL, нагрузка |
| Evidence | 0.67 эвристический порог, до двух цитат, sentence selector | Калибровка, применимость, сложные составные вопросы |
| Generation | Qwen3:8b, строго ограниченный JSON и E1/E2, локальный endpoint | Согласованный выбор модели, качество, расходы, политика передачи |
| Agent | Ограниченный MCP tool flow, host проверяет разрешения и ответ | Нужен ли вообще агент; полномочия и подтверждение действий |
| Актуальность | Не доказан lifecycle версий/автоматическая синхронизация | Источник истины, версии, удаление, отмена, переиндексация |
| Эксплуатация | Ограниченные localhost испытания | Наблюдаемость, latency/SLO, retention, аудит, backup, поддержка |

Не переносить точный cosine на большой корпус без измерения:
ограничение SQL по последним записям до scoring означает, что
релевантный старый документ может вообще не попасть в кандидаты.
Не представлять отсутствие результата как отсутствие сведений
во всей организации. Retrieval score не является confidence.
Порог и модель английского языка не доказывают качество на русском.

Дословный режим предпочтителен, если сотруднику нужен именно пункт
инструкции; генеративный — если требуется краткий синтез, проверяемый
по источникам; агент — только при обоснованном tool workflow.
Простой поиск, настройка готового продукта, RAG и локальный/облачный
варианты сравнивать на одном эталоне, не обещать универсального
превосходства или дешевизны собственной разработки.

## 5. Актуальность знаний: будущий контракт, не P1 backend

Для реального пилота владелец материала определяет: source_id,
version_id, effective_from/to, scope (продукт/территория/категория),
авторитетность, статус (draft/active/superseded/withdrawn), права.
Приоритет источника определяется бизнесом, а не сходством эмбеддингов
или временем загрузки. При неоднозначной применимости — уточнить
контекст или эскалировать; при двух конфликтующих применимых правилах
без утверждённого приоритета — показать конфликт и не выбирать число.

Пример C: 30 и 14 дней, обе учебные инструкции разрешены, нет
утверждённого приоритета. Только детерминированный отказ P1.
Если один документ относится к другому продукту или периодам,
это не обязательно противоречие. Не симулировать version resolution
как реальную возможность. Для будущей интеграции требовать атомарную
или явно согласованную смену видимой версии, актуальные ACL при чтении,
переиндексацию/удаление и регрессии при изменении источника.
Права на документ и его применимость — независимые фильтры.

## 6. Матрица доверия для публичного P1

| Свойство | Свидетельство | Не доказано |
|---|---|---|
| WAV/Markdown → готовый job и поиск | 09.11 real Chromium/Whisper/ONNX/PG | Большой корпус, PDF/OCR, русский ASR |
| Дословный ответ, отзыв права в следующем запросе | EVIDENCE-2026-11-09-ANSWER.md, live exact mode | Семантическая корректность всех выдержек |
| Локальная генерация с двумя цитатами | EVIDENCE-2026-11-09-QWEN.md, actual model | Faithfulness на независимой выборке |
| Отзыв в ходе генерации, отказ от ошибочного JSON/ID | Scripted-model PG/unit regression в протоколе Qwen | Живой Qwen race, абсолютное отсутствие TOCTOU |
| Два учебных профиля, actual tool/retrieval, свежий запрос после revoke | EP11-LIVE-QWEN-2026-11-15.md | Настоящий login/SSO, отзыв уже доставленной копии |
| Ограниченная MCP схема, проверка источников/действий | EP11-MULTIUSER.md, scripted regression | Универсальный агент, production security |
| Нет достаточных сведений / конфликт | Browser model A/C; отдельные abstain tests в evidence | Live конфликт версий, калиброванный отказ |
| Скорость и экономический эффект | 54.2 с видео полного A, 45/55 с full B | Latency/SLO, throughput, окупаемость |

Исторические цифры не результаты текущего запуска. Не объединять
67/67 Python/PG и 13/13 browser 09.11 с 121 Python и 36 browser
15.11 в единый итог или называть все real-model tests.
Source citation подтверждает происхождение и проверку прав в
ограниченном контексте, но ответ всё ещё semantic_verified=false.
Prompt injection/egress gates ограничивают риск, не гарантируют
отсутствие атак. При недоступности модели generated возвращает
503; evidence-only можно отдельно запросить, не обещать автоматический
fallback без отдельной реализации. Fresh-read revoke не стирает
скриншоты, логи и уже выданный ответ; после последней проверки есть
граница доставки, которую нельзя скрывать.

## 7. Как принять качество пилота заказчика

Зафиксировать corpus revision, эталон, профиль, ответы и baseline
до настройки; holdout не использовать для настройки порога.
Разметить каждое задание: ответимо ли именно разрешёнными и
применимыми источниками, допустимые фрагменты, обязательные факты,
недопустимые утверждения, требуемый отказ/уточнение. Ответ может
быть верным по общим знаниям, но unsupported в заданном корпусе.
Независимый эксперт заказчика разрешает спорные метки.

| Метрика | Расчёт и смысл |
|---|---|
| Retrieval hit@k | Доля ответимых вопросов, где найден хотя бы один эталонный фрагмент; отдельно multi-evidence coverage |
| Подтверждённый правильный ответ | Число ответимых вопросов с полным корректным и источниково подтверждённым ответом / число ответимых |
| False abstention | Отказ на ответимый вопрос / число ответимых |
| Unsupported answer | Содержательный ответ на неответимый вопрос / число неответимых |
| Citation validity | Точные разрешённые и применимые ссылки / все предъявленные ссылки; validity и semantic support отдельно |
| Groundedness | Подтверждённые утверждения / проверенные существенные утверждения; полнота отдельно |
| ACL critical | Любая выдача запрещённого содержания/метаданных или неправильный доступ — отдельный FAIL |
| Полное время решения | Поиск + чтение + проверка + эскалация; сравнить одинаковые задания и качество |

Порог stop/go согласовать до пилота; любой подтверждённый critical
fail блокирует выпуск затронутого сценария независимо от средних.
Отчёт — числитель/знаменатель, случаи ошибок, версия набора и режим.
Не делать статистических гарантий по 12–20 вопросам и не выдавать
синтетические результаты за эффект у клиента. Проверять на том же
наборе обычный поиск/FAQ и доступный готовый AI при согласованном
контуре данных. Не передавать закрытые источники внешнему evaluator.

## 8. Приёмка технического режима ET01–ET08

ET01: A → раскрыть трассу без reset; 09.11 путь и подлинные quote,
переводы, origin labels, два источника и ссылки.
ET02: A → убрать доступ; старый вывод очищен; новая выдержка/отказ
не маркированы как новый Qwen ответ; нет скрытого материала в выводе.
ET03: B → Alice/Bob/revoke; UI очищен, новый результат только для
выбранного профиля, реальные evidence отдельно; это не security test.
ET04: C → конфликт 30/14; метка синтетики и эскалация, без выбора
правила и ложной даты/версии; нет выдуманной уверенности.
ET05: матрица доверия → раздельные live/scripted/browser доказательства,
ссылки на точные протоколы и корректная дата/граница.
ET06: раскрыть ограничения; bounded retrieval, semantic_verified=false,
fresh-read vs delivered answer, 503 vs отдельный extractive request.
ET07: открыть пример пилота и сравнение альтернатив; не обещать
превосходство, не показать придуманные показатели качества.
ET08: сброс/отмена/смена режима; mobile 390px, клавиатура,
нет неожиданных запросов, рабочий CTA. Техническая панель не
вызывает LLM/PG и не требует регистрации.

P1 — EA01–EA12 + ET01–ET08, существующий видеофрагмент и протоколы.
Не добавлять полноценный benchmark, version management, IAM,
новый agent workflow или live backend ради демонстрации.
Они возможны в отдельном платном пилоте/доработке.
