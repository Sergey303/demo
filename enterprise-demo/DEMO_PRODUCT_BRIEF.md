# Enterprise AI — продуктовый сценарий P1

Проект, не описание реализованных возможностей. Коммерческий контекст:
COMMERCIAL-BRIEF.md. Существующие источники: README.md,
EVIDENCE-2026-11-09-QWEN.md, EP11-LIVE-QWEN-2026-11-15.md,
public-demos/build.py, model.mjs, ui.mjs, smoke.mjs.
Не изменять GosVet, AppForge, Reliable Jobs или live API в P1.

## 1. Цель

«Сотрудник получает ответ из разрешённых рабочих материалов, может
открыть точный фрагмент и понимает, когда требуется проверка человеком».
Основной сценарий — сотрудник поддержки отвечает на вопрос клиента.
Вход заполнен, до первого действия не требуется загрузка или регистрация.
Цель UX: 30–60 секунд до проверки источника (не измеренная длительность).
Два режима: «Рабочий сценарий» и раскрываемые «Технические доказательства».
Переключение не меняет данные и не выдаёт локальную модель за backend.

## 2. Набор данных и уровни подтверждения

Набор A — существующий исторический пример 09.11:
refund-policy.md, quote “Customers can request a refund within 30 days.”,
символы 26–72 (как в протоколе); refund-audio.wav, quote
“Customers can request a refund within thirty days.”, 0.00–3.00 с.
Qwen-ответ дословно из протокола. Два разрешённых источника, тот же
вопрос и исходные параметры — единственный случай воспроизведения
записанного ответа. Перевод на русский отдельно подписать «Перевод».
Не пересоздавать UUID, оценки similarity или аудио, которых нет.
Видео/скриншот относятся именно к A, не к B.

Набор B — исторический пример 15.11:
Alice → alice-refund-policy.md / Alice Harbor, Bob →
bob-refund-policy.md / Bob Valley; третий другой tenant недоступен.
Дословные ответы и job UUID — только из EP11-LIVE-QWEN-2026-11-15.md.
Если точный фрагмент оригинального документа не подтверждён,
не выдавать ответ Qwen за цитату; ссылка на протокол вместо выдумки.
В публичной модели показать два учебных профиля и fresh-read
после отзыва Alice; разрешённые видимые источники только своего
профиля, Bob остаётся независимым. Не изображать настоящий login,
администрирование пользователей или секреты/токены.

Набор C — отдельный синтетический учебный конфликт (не live evidence):
«Инструкция A: срок 30 дней» и «Инструкция B: срок 14 дней»,
обе разрешены, область применимости/приоритет не определены.
Ответ: «В разрешённых материалах указаны разные сроки. Не могу
подтвердить применимое правило; уточните у владельца инструкции».
Это детерминированная иллюстрация желаемого поведения, не доказательство
автоматического выявления конфликтов или версий текущим backend.
Не смешивать наборы A/B/C или представлять их как один live корпус.

## 3. Основной рабочий сценарий

Первый экран «Ответ сотруднику — с проверяемым источником».
Выбран вопрос «В течение какого срока клиент может запросить возврат?».
Варианты вопроса ограничены учебным корпусом; не рисовать свободный
чат с произвольными ответами, fake typing или загрузку файлов.
Кнопка «Показать ответ». Ответ короткий, источник рядом, тип
«Запись реального ответа», «Учебная выдержка» или «Учебный отказ».
Нажатие на источник раскрывает оригинал фрагмента, перевод, название,
позицию или таймкод и ссылку на подтверждение. Не делать вид, что
доступен полный документ/аудио, если в публичном пакете только фрагмент.
При необходимости открыть существующее видео отдельно.

Сценарии EA01–EA12:
| ID | Действие | Ожидание |
|---|---|---|
| EA01 | Открыть A, нажать «Показать ответ» | Дословный исторический ответ с 2 источниками; пометка replay |
| EA02 | Раскрыть документ и аудио | Точные quote/location, перевод отдельно, ссылка на доказательство |
| EA03 | Исключить документ, выполнить новый запрос | Только разрешённая аудио-выдержка, не replay Qwen |
| EA04 | Исключить оба, выполнить запрос | Нет разрешённых источников; нет ответа и цитат |
| EA05 | Вернуть доступ, выбрать доставку | Нет достаточных сведений, не придумывать |
| EA06 | Открыть B Alice, выполнить запрос | Источник Alice, записанный ответ при точном исходном состоянии |
| EA07 | Переключить B Bob | Очистить старый вывод; запрос показывает только Bob |
| EA08 | Вернуться к Alice, отозвать учебный грант | После нового запроса нет её источника; Bob не затронут |
| EA09 | Открыть C, задать вопрос | Обе учебные выдержки, конфликт, запрос проверки человеком |
| EA10 | Перейти к техническим доказательствам | История A/B отдельно, ограничения и рабочие ссылки |
| EA11 | Сбросить с подтверждением | Исходный A, оба разрешены, чистый вывод |
| EA12 | CTA «Проверить помощника на ваших рабочих вопросах» | Engineering, предвыбранная development; доступен путь возврата |

При смене профиля, набора, вопроса или прав очистить старый вывод
и показать «Выполните новый запрос». Это UX публичной модели,
не обещание принудительного удаления ранее полученных данных.
Отзыв в B выполняется только в учебной модели, обратим сбросом.
Профиль и grant controls помечены как имитация. Не отправлять
запросы к модели/БД/API и не сохранять пользовательские данные.
Все UI результаты выводятся из одной детерминированной модели,
не дублируются статическими обещаниями.

## 4. Технический уровень и границы

Показать схему фактического пути A: загрузка → durable job → ASR/ONNX →
PostgreSQL-grants → authorized retrieval → extractive selector →
локальная Qwen → проверка ответа/повторная проверка грантов → citations.
B: signed principal → agent → actual MCP search_evidence → PG/ONNX →
model/host validation → source-bound citations. Не смешивать реализации.
Точное название моделей и даты взять из протоколов. Указать, что
свободный текст семантически не верифицирован; цитаты подтверждают
происхождение и проверку разрешения в ограниченной схеме, не истинность.
Нет production IAM, SSO, непрерывных гарантий доступности, автоматической
актуализации, полного prompt injection protection, русскоязычного
quality benchmark. Человеческая проверка для критичных решений.

Матрица доказательств: реальная модель/HTTP/PG отдельно от scripted
regression и browser model. Исторические тесты не выдавать за новый
запуск. 09.11 и 15.11 — разные стенды, источники и endpoints.
Операционный вопрос: какие документы, допустимое размещение, ACL,
обновления, качество, стоимость; пилот по PILOT-ACCEPTANCE.md.

## 5. P1 приёмка и публикация

Проверить EA01–EA12, отрицательные состояния, отсутствие чужих
цитат в видимом выводе, reset/cancel, клавиатуру, мобильный 390px,
вложенный mount и CTA. Отсутствие неожиданных network requests;
историческое видео по явному действию, не autoplay.
Публичная модель не является доказательством backend ACL или retrieval.
Не добавлять загрузки/публичный сервер и не запускать дорогие модели
обязательно ради P1. При необходимости новый live тест только на
изолированной disposable DB и синтетике по отдельному заданию.
Существующие реальные evidence сохранять. Не заменять старые скриншоты
снимками симуляции без метки. Codex CLI независимое ревью, ручная
приёмка RDC, фактические скриншоты, обновить только Enterprise AI
в COMMERCIAL-HANDOFF.md и соответствующую карточку Engineering.
Не откладывать публикацию трёх принятых демо ради P1.
