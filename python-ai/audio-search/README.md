# Whisper transcript source attribution

A small independent building block for audio-search RAG: `core.transcribe()` runs the open-source OpenAI Whisper model locally and turns timestamped segments into validated searchable records. It preserves original audio filename and start/end timestamps. It **does not** claim speaker diarization, word-level alignment or evaluated transcription quality.

`python -m pip install openai-whisper` installs optional inference dependencies (PyTorch and FFmpeg system executable are also required). `python -c 'from core import transcribe; print(transcribe(__import__("pathlib").Path("sample.wav")))'` runs inference on your own local audio. `pytest -q tests` tests timestamp handling without fetching weights. No recording or model is bundled. To integrate with neural retrieval, embed each record's `text` and return its `source` and time range with each hit.

## Timestamped semantic search

`search.TranscriptIndex` connects timestamp-attributed Whisper records with an injected text embedding model, builds normalized exact-search vectors in bounded batches, and returns the original file, start/end seconds, text and similarity score. It supports multiple files, an optional source filter, and deterministic ties. Search costs O(Nd + N log k), without an approximate-index recall penalty. Use an embedding adapter with `encode(list[str])` (for example Sentence Transformers or a local ONNX embedding model). Tests inject a deterministic encoder to check indexing and timestamps without implying that a speech model ran.

For a standalone local query, install `fastembed` and run `python search_cli.py transcripts.json 'Where was the refund discussed?'`. The input is a JSON list of `core.transcribe()` records. The ONNX embedding model is downloaded on first run and is **not** verified end-to-end in the unit tests; inference and disk indexing are intentionally outside the demonstrated core. No remote paid API is required. The CLI indexes in memory on each invocation, so this is intended for small local datasets.

## End-to-end local speech-to-search pipeline

`pipeline.py` connects audio decoding and **real Whisper weights** (via the CPU-friendly `faster-whisper` CTranslate2 runtime) with ONNX semantic embeddings (`fastembed`), exact cosine retrieval and timestamped results. It handles multiple audio files, including files with zero speech segments, and reports separate transcription/index/search times. No paid API is needed; model weights are downloaded on first use.

```bash
python -m pip install faster-whisper fastembed numpy
# ffmpeg with libflite installed: deterministic synthetic speech, no third-party audio assets
ffmpeg -f lavfi -i "flite=text='The refund policy allows customers to return their purchase within thirty days':voice=slt" -ar 16000 -ac 1 sample.wav
python pipeline.py sample.wav --question 'What is the refund policy?' --k 1
pytest -q tests
```

This is **speech transcription + vector search**, not diarization or word-level timestamp alignment. For retrieval quality claims, evaluate with a larger labeled audio corpus and holdout queries. The test suite uses injected encoder/transcriber boundaries; a genuine end-to-end model check additionally requires the model weights and audio above.

### Verified first full run in RDC (2026-11-01)

The reproducible FFmpeg/Flite `sample.wav` command above was executed on CPU. `faster-whisper` (`tiny.en`, int8) recognized: *“The refund policy allows customers to return their purchase within 30 days.”* The ONNX encoder ranked that segment first for *“What is the refund policy?”*, source `demo-audio-sample.wav`, timestamp **0.0–5.0 seconds**, cosine similarity **0.765867**. Timings: **4.948 s** transcription; **74.056 s** embedding/index setup **including first model download**; **0.00864 s** vector search. This is one observed local run, not a benchmark or a general accuracy claim. Source audio is generated by the documented command and is not committed.

The pipeline decodes audio to float32/16 kHz PCM using FFmpeg before passing it to CTranslate2, avoiding PyAV API compatibility differences (`metadata_errors`) observed in the RDC setup.

## Reproducible multi-audio evaluation

`python evaluate_audio.py` constructs six short **synthetic** single-speaker English recordings via FFmpeg/Flite (refunds, shipping, password recovery, billing, privacy, support), transcribes each with actual Whisper (`faster-whisper` tiny.en on CPU), embeds the transcripts using `fastembed`/BGE-small, then checks the top-1 and top-3 ranked source filenames for six held-as-queries semantic questions. Audio is generated in a temporary directory and automatically discarded. No private voice data or API calls are involved; model weights download on the first run. This evaluation covers the complete pipeline, unlike the injected-boundary unit tests.

**Observed RDC run, 2026-11-01:** 6 audio files, 6 transcribed segments, 6 questions; recall@1 = **6/6**, recall@3 = **6/6**; summed transcription time **8.399 seconds**, search latency **p50 4.70 ms** (six queries; model inference during query included). The questions and source text were jointly authored, the voice is synthesized, and the corpus is very small; these results **must not** be presented as blind generalization, real-speaker accuracy, or p95/p99 SLOs. A stronger next evaluation would use independently collected multi-speaker recordings and blind labels.

### Harder multi-topic and out-of-domain evaluation

`python evaluate_challenges.py` synthesizes **four multi-topic audio recordings** (seven detected Whisper segments in the observed run) and evaluates eight independently phrased search questions against the expected source recordings. It also checks a deliberately unanswerable driver's-license question. Source-level scoring is used, not timestamp-level verification. This is a reproducible *small synthetic challenge*, not a blind real-audio evaluation.

**Observed RDC run (2026-11-01):** Recall@1 **5/8 = 62.5%**, Recall@3 **8/8 = 100%**, transcription across all four recordings **9.497 s**. The top-ranked source was incorrect for account recovery, recruiting and database backup questions (all three correct sources ranked third). Recall@3 is weak on a four-source corpus (random ranking would put the correct source in the first three positions with 75% probability). The out-of-domain question incorrectly returned `meeting_b.wav` with cosine score **0.495003**, because the current exact top-k search **has no abstention mechanism**. No threshold is inferred from this single negative case. More challenging, independent speech and a larger corpus are required for meaningful quality claims.

### Sentence splitting ablation (same four recordings)

`evaluate_challenges.py` now compares native Whisper segments to `semantic_chunks.split_records()` on the **same decoded/transcribed audio and eight labeled questions**, deduplicating sources before calculating source-level Recall@k. **RDC result, 2026-11-01:** baseline 7 Whisper passages, Recall@1 **5/8**, Recall@3 **8/8**; sentence splitting 8 passages, Recall@1 **5/8**, Recall@3 **8/8**. The account-recovery and database-backup questions still ranked third; recruiting improved from third to second but remained incorrect at top-1. **Conclusion: sentence splitting alone did not improve top-1 retrieval** on this dataset. Sentence timestamps within a Whisper segment are proportional estimates, not word alignment. The unanswerable question was still assigned a result; abstention requires independently evaluated calibration, not an ad hoc threshold fitted to one query.
