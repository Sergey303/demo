# EAI-02 — Local ONNX Runtime CPU inference

## The model and its provenance

The script `build_model.py` creates **a small actual logistic regression classifier trained on reproducible artificial request windows**, then exports it to ONNX with the standard `MatMul`, `Add` and `Sigmoid` operations (opset 13, IR 8). This is a real generated model graph and native runtime, but **not a real-world trained anti-DDoS detector**.

- No external weights, proprietary datasets, account keys, HTTP requests or downloads occur in build/inference scripts.
- All training labels are *authored synthetic* data generated by an explicit artificial rule with seeded randomness.
- The `artifacts/` folder is git-ignored; `model.onnx` and `manifest.json` are generated locally. Nothing silently downloads a model.
- Manifest tracks model identity, feature order, opset, SHA-256 of the ONNX model, generator source hash, seed and label provenance. The loader bounds artifact reads and rejects incompatible manifest fields or a mismatch between model bytes and the recorded digest.
- SHA256 is an integrity check against accidental changes; a locally writable manifest is **not** a cryptographic signature or secure software supply-chain solution.

## Run (Python 3.12+, CPU)

From this directory, create a dedicated virtual environment and install the pinned CPU dependencies:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir --only-binary=:all: -r requirements.txt
.venv/bin/python -B build_model.py
.venv/bin/python -B runtime.py \
  --window-json '{"requests":250,"seconds":10,"errors":45,"baseline_rps":3}'
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B benchmark.py --iterations 50
```

All input fields are numeric, bounded, versioned and independent of IPs/users/PII: `requests`, `seconds`, `errors`, `baseline_rps`. The feature transformer produces four normalized numbers. `OnnxWindowScorer.score_many` strictly limits batches to **1..32 windows**, verifies model SHA256 and the rank-2 float input/output contract with a shared dynamic batch dimension, initializes `CPUExecutionProvider` explicitly and calls `InferenceSession.run()`.

The benchmark records actual local model initialization latency and p50/p95/p99 **warm CPU inference** on synthetic holdout features. These are not measurements of network latency, real detection quality, cloud costs, or performance on an actual edge device.

## Verified CPU run (2026-11-23)

The commands above ran on Linux x86-64 with an Intel Core i5-12400 and Python 3.12.14 in a local venv using NumPy 2.2.6, ONNX 1.19.1 and ONNX Runtime 1.23.2. The generator, scorer and benchmark used locally generated synthetic artifacts. The scorer returned `0.3778071105480194` for the example window, and all 11 tests passed (4 feature, 7 native-model tests). Coverage includes reproducible model bytes, artifact integrity, fixed-batch rejection despite a matching hash, the 32-window batch boundary and agreement with NumPy.

- Model SHA-256 `51a458cab734c3f33836940c325feeddce8da966527f586b53e454af5c7ff109`
- Synthetic holdout label SHA-256 `cb37b04e8bb901980279dd92c55553feceeb415f791269de184fe6fe8740876c`
- Session initialization including artifact loading and checks took **45.9863 ms**. With 5 warmups and 50 single-window timed calls, warm p50/p95/p99 were **0.0059 / 0.0084 / 0.0490 ms**.

This verification covers the standalone CPU path. CI, remote hardware and cross-project integration were outside this run.
