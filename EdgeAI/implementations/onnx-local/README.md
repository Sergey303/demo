# EAI-02 — Local ONNX Runtime CPU inference

**Status: implementation + runnable CPU tests committed; native runtime execution not yet confirmed on rdc-project** (remote machine disconnected during this increment). The separate GitHub Actions `onnx-cpu` job installs dependencies, generates the model and must perform *real native inference*; a pure mock or a skipped test is not accepted as verification.

## The model and its provenance

The script `build_model.py` creates **a small actual logistic regression classifier trained on reproducible artificial request windows**, then exports it to ONNX with the standard `MatMul`, `Add` and `Sigmoid` operations (opset 13, IR 8). This is a real generated model graph and native runtime, but **not a real-world trained anti-DDoS detector**.

- No external weights, proprietary datasets, account keys, HTTP requests or downloads occur in build/inference scripts.
- All training labels are *authored synthetic* data generated by an explicit artificial rule with seeded randomness.
- The `artifacts/` folder is git-ignored; `model.onnx` and `manifest.json` are generated locally. Nothing silently downloads a model.
- Manifest tracks model identity, feature order, opset, SHA256 of the ONNX model, generator source hash, seed and label provenance. The inference loader refuses missing/altered/unexpected models.
- SHA256 is an integrity check against accidental changes; a locally writable manifest is **not** a cryptographic signature or secure software supply-chain solution.

## Run (Python 3.12+, CPU)

From the repository root:

```bash
python3 -m pip install -r EdgeAI/implementations/onnx-local/requirements.txt
python3 EdgeAI/implementations/onnx-local/build_model.py

python3 EdgeAI/implementations/onnx-local/runtime.py \
  --window-json '{"requests":250,"seconds":10,"errors":45,"baseline_rps":3}'

python3 EdgeAI/implementations/onnx-local/benchmark.py --iterations 50
python3 -B -m unittest discover -s EdgeAI/implementations/onnx-local/tests -v
```

All input fields are numeric, bounded, versioned and independent of IPs/users/PII: `requests`, `seconds`, `errors`, `baseline_rps`. The feature transformer produces four normalized numbers. `OnnxWindowScorer.score_many` strictly limits batches to **1..32 windows**, verifies model SHA256 and expected tensor contract, initializes `CPUExecutionProvider` explicitly and calls `InferenceSession.run()`.

The benchmark records actual local model initialization latency and p50/p95/p99 **warm CPU inference** on synthetic holdout features. These are not measurements of network latency, real detection quality, cloud costs, or performance on an actual edge device.

## Integration with the third project

```bash
python3 EdgeIntegratedScenarios/ai-assisted-ddos-defense/onnx_replay.py
python3 -B -m unittest discover -s EdgeIntegratedScenarios/onnx-tests -v
```

This genuinely executes ONNX inference if the dependencies and generated model exist, then passes the score into the **existing safety-first policy**: at most `allow → observe`; a model score alone never hard-blocks. Reports stay `status=simulated` because the labelled traffic and rule decisions remain synthetic.
