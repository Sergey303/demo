# EAI-02 — Local ONNX Runtime CPU inference

## The model and its provenance

The script `build_model.py` creates **a small actual logistic regression classifier trained on reproducible artificial request windows**, then exports it to ONNX with the standard `MatMul`, `Add` and `Sigmoid` operations (opset 13, IR 8). This is a real generated model graph and native runtime, but **not a real-world trained anti-DDoS detector**.

- No external weights, proprietary datasets, account keys, HTTP requests or downloads occur in build/inference scripts.
- All training labels are *authored synthetic* data generated by an explicit artificial rule with seeded randomness.
- The `artifacts/` folder is git-ignored; `model.onnx` and `manifest.json` are generated locally. Nothing silently downloads a model.
- Manifest tracks model identity, feature order, opset, SHA-256 of the ONNX model, generator source hash, seed and label provenance. The loader caps the manifest at 16,384 bytes and the model at 1,000,000 bytes. It rejects duplicate or unexpected manifest fields, incompatible metadata, a builder-source digest mismatch and model digest mismatch. Before ONNX Runtime starts, it validates the protobuf against the builder's exact graph contract. Only the default-domain `MatMul → Add → Sigmoid` graph is accepted, with fixed-size finite embedded weights and bias bounded to magnitude 100, fixed metadata and a shared dynamic batch dimension. ONNX Runtime receives a reconstructed graph.
- SHA256 is an integrity check against accidental changes; a locally writable manifest is **not** a cryptographic signature or secure software supply-chain solution.

## Run (Python 3.12+, CPU)

From this directory, create a dedicated virtual environment and install the pinned CPU dependencies:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir --only-binary=:all: -r requirements.txt
.venv/bin/python -B build_model.py
.venv/bin/python -B runtime.py \
  --window-json '{"requests":250,"seconds":10,"errors":45,"baseline_rps":3}'
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B benchmark.py --iterations 50
```

All input fields are numeric, bounded, versioned and independent of IPs/users/PII: `requests`, `seconds`, `errors`, `baseline_rps`. The feature transformer produces four normalized numbers. `OnnxWindowScorer.score_many` strictly limits batches to **1..32 windows**, verifies model SHA256 and the rank-2 float input/output contract with a shared dynamic batch dimension, initializes `CPUExecutionProvider` explicitly and calls `InferenceSession.run()`.

The benchmark records actual local model initialization latency and p50/p95/p99 **warm CPU inference** on synthetic holdout features. These are not measurements of network latency, real detection quality, cloud costs, or performance on an actual edge device.

## Standalone scoring with a wall-clock deadline

From this directory after building artifacts:

```python
from pathlib import Path
from isolated import IsolatedWindowScorer

scorer = IsolatedWindowScorer(Path("artifacts"), timeout_seconds=2.0)
result = scorer.score({"requests": 250, "seconds": 10, "errors": 45, "baseline_rps": 3})
print(result.mode, result.scores, result.reason)
```

`score_many` accepts 1–32 windows and returns an immutable result in input order. Invalid input raises `ValueError` before launch. A successful result uses `mode="onnx-cpu"` and `reason=None`. A deadline breach uses `mode="rule-only"` and `reason="timeout"`. Worker startup, missing dependencies or artifacts, rejected artifacts and invalid replies use `reason="unavailable"`. The entire fallback batch uses the existing traffic scenario baseline.

The one-shot Linux worker uses CPU only and needs `libseccomp.so.2`. The filter blocks socket creation, io_uring setup and further program execution before the worker imports ONNX or reads artifacts. Launch uses a fixed executable and script, no shell, a minimal environment and no inherited application descriptors. Requests are capped at 4 KiB and replies at 2 KiB. A monotonic deadline covers worker startup, model loading, inference, reading the reply and child exit. On timeout the parent sends SIGKILL and reaps the child. Process creation, scheduling and kernel-level reap can add latency outside the configured budget.

The parent imports with only the Python standard library and local modules. Missing Linux confinement or a non-Linux platform uses the rules fallback. Use trusted local interpreter, packages and artifact directory. The filter does not impose a filesystem sandbox or CPU/RAM quotas.

## Verified CPU run (2026-11-23)

The initial in-process acceptance commands ran on Linux x86-64 with an Intel Core i5-12400 and Python 3.12.14 in a local venv using NumPy 2.2.6, ONNX 1.19.1 and ONNX Runtime 1.23.2. The generator, scorer and benchmark used locally generated synthetic artifacts. The scorer returned `0.3778071105480194` for the example window, and all 11 tests passed (4 feature, 7 native-model tests). Coverage includes reproducible model bytes, artifact integrity, fixed-batch rejection despite a matching hash, the 32-window batch boundary and agreement with NumPy.

- Model SHA-256 `51a458cab734c3f33836940c325feeddce8da966527f586b53e454af5c7ff109`
- Synthetic holdout label SHA-256 `cb37b04e8bb901980279dd92c55553feceeb415f791269de184fe6fe8740876c`
- Session initialization including artifact loading and checks took **45.9863 ms**. With 5 warmups and 50 single-window timed calls, warm p50/p95/p99 were **0.0059 / 0.0084 / 0.0490 ms**.

This verification covers the standalone CPU path. CI, remote hardware and cross-project integration were outside this run.

## Standalone hardening verification

On Linux x86-64 with Python 3.12.14, NumPy 2.2.6, ONNX 1.19.1 and ONNX Runtime 1.23.2, `python -B -m unittest discover -s tests -v` passed all **20 tests**. The subprocess test compares all 32 native CPU scores with the in-process reference. Deadline tests use 150 ms and verify both SIGKILL and that `waitpid` finds no child left to reap, including when stdout closes before exit. Other tests cover oversized and invalid responses, deterministic fallback, EPERM on socket creation, tampered manifests, malformed model bytes, unsupported operators, external data and size limits.

The generated model retained SHA-256 `51a458cab734c3f33836940c325feeddce8da966527f586b53e454af5c7ff109`. Both the original CLI and the isolated API scored the example at `0.3778071105480194`. The 50-iteration in-process benchmark reported 22.1821 ms session initialization and warm p50/p95/p99 of 0.0034 / 0.0052 / 0.0057 ms. These timings exclude subprocess startup.
