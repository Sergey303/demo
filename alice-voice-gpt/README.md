# Alice Voice GPT — домашний навык Алисы через Codex CLI

**Статус:** локальный прототип, не публично подключённый навык. Для Яндекс Станции Мини 2 (YNDX-00020), без перепрошивки.

Схема: «Алиса, спроси у домашнего собеседника, ...» → Яндекс Диалоги → `https://alice.knowledge-pilot.duckdns.org/alice/<TOKEN>` → единственный хостовый Windows-сервис `KnowledgePilotCaddy` → `127.0.0.1:18765` → отдельный Linux/Docker-контейнер с .NET 10 и `codex exec` через ChatGPT OAuth.

**Отдельный платный OpenAI API-ключ не нужен.** Codex использует лимиты и возможные дополнительные кредиты тарифа ChatGPT. Это временный прототип: Codex предназначен для задач программирования, а не как полноценный голосовой API. Вызов CLI может занять десятки секунд, а вход через ChatGPT иногда требуется повторять.

**Иконка навыка Яндекса:** `assets/alice-skill-icon.png` (512×512 PNG) — нейтральный пример, который можно заменить в настройках приватного навыка.

## Установка (Windows PowerShell)

Код хранится в репозитории `Sergey303/demo/alice-voice-gpt`. Рабочая копия — **вне Git и rdc-project**, например `D:\services\alice-voice-gpt`.

```powershell
$src = 'D:\projects\ChatPilotGroup\demo\alice-voice-gpt'
& "$src\scripts\Install-AliceVoiceGpt.ps1" -Destination 'D:\services\alice-voice-gpt'
Set-Location 'D:\services\alice-voice-gpt'
docker compose config --quiet
docker compose build
```

Однократная авторизация **отдельного контейнера** через ChatGPT:

```powershell
docker compose run --rm --entrypoint codex app login --device-auth
docker compose run --rm --entrypoint codex app login status
docker compose up -d
docker compose ps
curl.exe -i http://127.0.0.1:18765/health
```

Команда входа выдаст адрес и одноразовый код для подтверждения в браузере. Не передавайте код кому-либо. Авторизацию в Chromium внутри `rdc-project` использовать не надо: у контейнера свой OAuth в изолированном Docker volume `alice-voice-gpt_codex_auth`. **Не монтируйте основной домашний `~/.codex`** и не копируйте его `auth.json`. API-ключ OpenAI для этого варианта не используется.

При обновлениях: повторить установщик, затем `docker compose up -d --build`. Установщик не перезаписывает `.env` и секретный токен. Код не редактируется внутри действующего контейнера.

## Приватный навык Яндекс Диалогов

1. Создайте навык в https://dialogs.yandex.ru/development, настройте его как приватный и выберите нейтральное активационное имя («домашний собеседник», если Яндекс одобрит).
2. Используйте URL `https://alice.knowledge-pilot.duckdns.org/alice/<TOKEN>`, подставляя значение `secrets/alice_webhook_token` из Windows-каталога установки.
3. Укажите выданный `skill_id` в `.env`: `YANDEX_SKILL_ID=<ID>`. Выполните `docker compose up -d`.
4. Проверьте HTTPS с публичного устройства, затем запрос через симулятор Яндекса и колонку. Однофразовый запуск зависит от распознавания команд и настроек навыка Яндекса.

Файл `Caddyfile.alice.caddy` предназначен для **существующего** `KnowledgePilot.Deploy/edge/caddy/sites-enabled/`: установите только этот сайт через принятый deploy-процесс, `caddy validate` и `caddy reload`. Не создавайте вторую службу Caddy и не перенастраивайте общий Caddyfile. DNS сам по себе не подтверждает работоспособность HTTPS.

## Асинхронные ответы, лимиты, безопасность

Яндекс ждёт примерно 4,5 секунды. Мы ждём результат не более 2,6 секунды, а затем говорим: «Думаю над ответом. Скажи: ответ». До 75 секунд Codex работает внутри контейнера; повторное «ответ» забирает готовый результат. Это **не** потоковая озвучка и не долговечная очередь: при рестарте незавершённый ответ теряется. После готового ответа текущая сессия навыка завершается.

- CLI запускается `codex exec --ephemeral --sandbox read-only`, с отключением инструментов shell/unified_exec/browser/apps, без исходников, Git и директории `rdc-project` внутри контейнера. Не подключайте контейнер к Docker socket.
- До 2 одновременных запросов к Codex, до 30 новых вопросов в сутки на пользователя по умолчанию (лимит хранится в RAM и обнуляется после рестарта). Это не гарантированное ограничение расходов.
- Секрет вебхука проверяется до обработки запроса; `YANDEX_SKILL_ID` — дополнительная проверка, **не криптографическое удостоверение отправителя**. Если URL с секретом утечёт, доступ возможен без Яндекса: не публикуйте его.
- Запросы/ответы не выводятся в application-логи; Docker json-file имеет ротацию. `/health` доступен только на localhost Windows; Caddy публикует только `/alice/*`.
- Оболочка контейнера read-only, привилегии и Linux capabilities сняты, память 768 MiB. Однако read-only sandbox не предотвращает *чтение* файлов, поэтому не давайте этому контейнеру доступ к ценным данным. Отключение tools следует повторно проверять при обновлениях Codex CLI.
- Неизменяемые при публикации секреты и OAuth-хранилище должны оставаться вне Git. Удаление Docker volume удалит авторизацию.

## Проверки

```bash
bash tests/run-smoke.sh
docker compose config --quiet
docker compose build
```

Smoke-тест использует `DEMO_MODE=true`, не потребляет лимиты Codex и не требует доступа к Яндексу. Для реального теста Codex через контейнер сначала выполните `codex login --device-auth`. Для повторных запросов нужны реальные OAuth-кредиты и доступность OpenAI.

Операции: `docker compose ps`, `docker compose logs --tail=50 app`, `docker compose restart`. Healthcheck обнаруживает сбой, но сам по себе не перезапускает процесс в статусе `unhealthy` (restart-policy работает при выходе процесса).

## Ограничения прототипа

- Никаких обещаний работы без платного API **при исчерпании лимитов подписки**.
- Время ответа Codex может быть существенно больше тайм-аута Яндекса.
- Модель Codex может не отвечать как обычный бытовой помощник и не имеет полноценной памяти разговора.
- Публичный маршрут Caddy и приватный навык пока требуют отдельной настройки и реальной проверки.
